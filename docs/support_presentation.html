02 — Contexte

Pourquoi ce projet ?

Les communautés de modding de jeux vidéo s'organisent souvent autour d'outils génériques (forums, Discord) mal adaptés au suivi structuré d'un mod : versions, compatibilité, retours qualitatifs.

ModHub centralise la publication, le suivi de versions et les retours communautaires autour des mods.

05 — Bloc 1 : front-end

Maquette → statique → dynamique

  • Maquette — wireframes basse fidélité des écrans clés avant implémentation
  • Statique — CSS Grid / Flexbox, jetons de couleur centralisés, sans framework externe
  • Dynamique — recherche avec debounce, contexte d'auth React, routes protégées par rôle
06 — Bloc 2 : back-end

SQL et NoSQL, un vrai usage double

La création d'un mod illustre la collaboration des deux bases :

  1. Écriture de l'entité Mod en PostgreSQL (Prisma)
  2. Écriture des métadonnées spécifiques au jeu en MongoDB
  3. Journalisation de l'événement dans le fil d'activité MongoDB

Vérifié par un test d'intégration qui contrôle les deux bases après l'appel API.

07 — Sécurité

Mesures appliquées

  • Mots de passe hachés (bcrypt), message d'erreur générique anti-énumération
  • Autorisation vérifiée côté service (propriété, rôle admin)
  • Erreurs centralisées : pas de fuite de stack trace au client
  • Rate limiting sur l'authentification, CORS restreint
  • Row Level Security activée sur les tables Supabase
08 — Tests

Tests d'intégration bout-en-bout

Les tests exercent l'application réelle contre les vraies bases de développement (pas de mocks) pour valider un comportement effectif plutôt qu'une simulation.

9 / 9 tests passent — auth + cycle de vie complet d'un mod (SQL + NoSQL)

09 — Bilan

Difficultés rencontrées

  • Pas de Docker fonctionnel en local → bascule vers Postgres managé (Supabase)
  • Changement d'API majeur dans Prisma 7 (driver adapters) → vérification directe plutôt qu'hypothèse
  • Typage strict Express 5 sur les paramètres de route → garde-fou dédié
09 — Bilan

Perspectives

  • Upload de fichiers réel pour les versions de mods
  • Notifications temps réel (WebSocket) sur le fil d'activité
  • Tags libres en complément des catégories
  • Tests end-to-end côté interface (Playwright)
